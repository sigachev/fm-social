## CP5 (c) Phase 1 PR-1: fm-social internal-follows API

### What this PR ships
- New `FollowsInternalController` exposing 4 endpoints under
  `/api/internal/follows/*` for backend-to-backend calls from finmates-main
  and finmates-crypto.
- 3 new repository methods on `FollowRepository`: `findAllMateIds`,
  `findAllFollowingIds`, `findRecentFollowers`.
- Caffeine cache (60s TTL, 10k max, distinct key prefixes per endpoint).
- 13 controller-slice tests passing.

### Gate 0 — DISMISSED, replaced by static verification

The original Gate 0 (EXPLAIN ANALYZE on `findAllMateIds` before merge) is
dismissed, not deferred. Empirical query-plan verification at this stage
is impossible because fm-social's `follows` table has no realistic data
(V16 dropped legacy social-graph data on 2026-04-27; no seed data exists).
PG's planner will pick Seq Scan at this scale regardless of index quality,
making any pre-merge EXPLAIN ANALYZE a false negative.

**Replaced by:** static verification of index coverage. V16 ships
`(follower_id, status)` and `(followed_id, status)` composite indexes on
`follows`, which match the query shape generated by `findAllMateIds`.
Schema-vs-query alignment confirmed by code review.

**Empirical verification deferred to:** `cp5-c-design.md` §5 step 4
(production watch period after `finmates.fm-social.enabled=true` flag
flip). If `pg_stat_statements` or fm-social slow-query logs show Seq
Scans on `follows` once real traffic hits,
`V17__follows_covering_indexes.sql` ships as a hotfix. Pre-staged in
diagnostic at `fm-social/docs/cp5-c-pr1-gate-0-diagnostic.md`.
